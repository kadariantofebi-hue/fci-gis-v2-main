# Plan: Analisa gap MVP saat ini terhadap main PRD SIMANTA v1.3.6

## Goal

Menganalisa kondisi MVP frontend/mock yang ada di project sekarang terhadap main PRD terbaru `docs/PRD_WebGIS_Pemetaan_Wilayah.md` versi 1.3.6, lalu menyusun daftar improvement yang perlu dilakukan agar MVP sebelumnya tetap relevan dengan kebutuhan terbaru.

Fokus plan ini adalah analisa dan rencana kerja, bukan implementasi.

## Current context / assumptions

### Referensi PRD terbaru

Main PRD saat ini:

- Path: `docs/PRD_WebGIS_Pemetaan_Wilayah.md`
- Versi: 1.3.6
- Scope penting v1.3.6:
  - Single active OPD mode berlaku permanen untuk seluruh produk, termasuk pasca-MVP.
  - Tidak ada active scope untuk multi-OPD, CRUD OPD tambahan, statistik/filter lintas OPD, transfer aset antar-OPD, atau relokasi antar-OPD.
  - Modul OPD adalah Profil OPD Pengguna, bukan manajemen daftar OPD.
  - Modul Proyek GIS memakai `projects`, `project_documents` sebagai header metadata, dan `project_document_files` sebagai file/lampiran fisik multi-file.
  - Project GIS v1.3.6 menambah hardening: `project_members` untuk scope `assigned_project`, `version` pada `project_documents` dan `project_document_files`, enum/check status dokumen/file/payment, audit taxonomy untuk `project`, `project_document`, `project_document_file`, `project_payment`, dan constraint tepat satu OPD aktif/default.

### Kondisi MVP project saat ini yang terinspeksi

Frontend MVP berada di `frontend/` dan masih bersifat contract-first mock:

- `frontend/README.md` menyatakan semua mutasi masih mock in-memory/localStorage.
- `frontend/package.json` memiliki quality gate `npm run verify:mvp` yang menjalankan check, unit test, build, E2E, dan a11y.
- Source utama yang relevan:
  - `frontend/src/routes/dashboard/+page.svelte`
  - `frontend/src/routes/opd/+page.svelte`
  - `frontend/src/routes/projects/+page.svelte`
  - `frontend/src/routes/projects/create/+page.svelte`
  - `frontend/src/routes/projects/[id]/edit/+page.svelte`
  - `frontend/src/routes/projects/[id]/documents/+page.svelte`
  - `frontend/src/routes/projects/[id]/payments/+page.svelte`
  - `frontend/src/lib/services/api/opd.ts`
  - `frontend/src/lib/services/api/projects.ts`
  - `frontend/src/lib/mocks/opd.ts`
  - `frontend/src/lib/mocks/projects.ts`
  - `shared/src/enums.ts`
  - `shared/src/schemas/project.ts`
  - `shared/src/schemas/opd.ts`
  - `frontend/tests/e2e/frontend-mvp.spec.ts`

### Keputusan stakeholder terbaru untuk rencana ini

Jawaban user terhadap open questions plan ini menetapkan arah berikut:

1. Ada satu OPD aktif/default yang harus ditampilkan di MVP. MVP harus memakai OPD aktif/default tersebut secara eksplisit, bukan daftar OPD aktif. Nama/kode final OPD aktif perlu diambil dari fixture/config implementasi atau dikonfirmasi bila belum tertulis di repo.
2. Sub OPD/Bidang/UPT tidak perlu masuk MVP frontend sekarang, baik di Profil OPD, form aset, maupun form proyek.
3. Project GIS MVP perlu **mock upload multi-file interaktif**, bukan hanya fixture statis atau placeholder download.
4. Role `Finance` tidak perlu dipertahankan. Fitur pembayaran belum diperlukan sebagai workflow; MVP hanya perlu mencatat/menampilkan **history pembayaran** sebagai riwayat/referensi administratif proyek.
5. Implementasi berikutnya tetap **frontend only** sampai user selesai review hasil frontend.

### Gap besar yang terlihat dari inspeksi awal

1. MVP masih membawa asumsi multi-OPD di beberapa tempat:
   - `frontend/src/lib/mocks/opd.ts` berisi 5 OPD aktif.
   - `frontend/src/routes/opd/+page.svelte` masih menyediakan form tambah OPD, edit OPD, delete OPD, search, pagination, dan teks “transfer aset terlebih dahulu”. Ini bertentangan dengan PRD v1.3.6 yang menjadikan OPD sebagai Profil OPD Pengguna dan menghapus CRUD OPD tambahan/transfer antar-OPD dari active scope.
   - `frontend/src/lib/services/api/opd.ts` masih expose `listOpd`, `saveOpd`, dan `softDeleteOpd` dengan endpoint real `/opd/:id` dan DELETE, padahal PRD v1.3.6 aktifnya `/api/v1/opd/current`, `PUT /api/v1/opd/current`, dan `GET /api/v1/opd` hanya alias/list kompatibilitas yang mengembalikan OPD aktif/default.
   - `frontend/src/routes/dashboard/+page.svelte` masih punya grouping `jenis | opd`, kartu “Distribusi OPD”, dan copy “berdasarkan jenis aset atau OPD”. PRD terbaru menyatakan tidak ada statistik lintas OPD; dashboard/laporan single OPD hanya boleh memakai OPD aktif/default implisit.
   - `frontend/src/lib/services/api/projects.ts` masih menerima filter `opdId` dan mock project tersebar di beberapa OPD.
   - Test E2E masih mengharapkan “Tambah mock” OPD dan “OPD proyek” select.

2. Shared contract Project GIS belum selaras dengan PRD v1.3.6:
   - `shared/src/enums.ts` masih punya `ProjectStatus` tanpa `contracted` dan `archived` yang ada di PRD, dan `ProjectDocumentKind` belum lengkap (`rup_reference`, `aanwijzing_ba`, `evaluation_ba`, `winner_appointment`, `deliverable_list`, `receipt`, `maintenance_report`, `change_request`, `other`, dll).
   - `shared/src/schemas/project.ts` masih menganggap `ProjectDocument` sebagai satu row dengan `filename`, `scanStatus`, `checksum`, `uploadedBy`, `uploadedAt`; belum memisahkan header dokumen dan file fisik (`ProjectDocumentFile[]`).
   - `verificationStatus` masih `draft | pending | verified | rejected`, sedangkan PRD v1.3.6 memakai `draft | incomplete | submitted | verified | rejected`.
   - `scanStatus` masih `not_scanned | clean | warning`, sedangkan PRD v1.3.6 memakai `pending | clean | blocked`.
   - `paymentStatus` masih `referenced | paid_reference | pending_reference`, sedangkan PRD v1.3.6 memakai `draft | submitted | verified | paid | rejected | cancelled`.
   - `project_documents.version` dan `project_document_files.version` belum tercermin di shared schema/mock UI.

3. Modul dokumen proyek masih lebih dekat ke model lama satu dokumen = satu file:
   - `frontend/src/routes/projects/[id]/documents/+page.svelte` menampilkan field `filename`, `scanStatus`, `checksum`, uploader langsung di dokumen.
   - Belum ada UI header dokumen + daftar file/lampiran per header.
   - Belum ada status `incomplete`, validasi “tidak bisa verify jika tidak ada file aktif clean”, file label/order/version, atau sensitivity inheritance secara eksplisit dari header ke file.
   - Audit download mock mencatat `documentId` dan `projectId`, tetapi belum punya `fileId` sesuai PRD v1.3.6.

4. Permission/RBAC belum mengikuti taxonomy PRD terbaru:
   - `shared/src/enums.ts` masih memakai permission ringkas seperti `asset:write`, `opd:write`, `project:write`.
   - PRD memakai permission lebih granular seperti `asset:create`, `asset:update`, `opd:update`, `project:create`, `project:update`, `project:document_verify`, dll.
   - `project:document_verify`, `assigned_project`, dan taxonomy audit project belum terlihat sebagai contract frontend/mock.

5. UI metadata masih menampilkan label lama:
   - `frontend/src/lib/components/layout/Sidebar.svelte` masih menampilkan `PRD v1.3.3`.
   - `frontend/README.md` masih menyebut upload/download/import/export/atlas/audit backend placeholder post-MVP, padahal PRD v1.3.6 dan keputusan stakeholder terbaru memasukkan pencatatan proyek GIS + header dokumen upload multi-file interaktif ke MVP frontend mock, sementara scan/quarantine nyata tetap Go-live Hardening/backend.

6. Role/fitur pembayaran perlu disederhanakan:
   - MVP masih punya role `Finance` di shared enum/user fixtures dan permission helper sensitif.
   - User sudah menetapkan role Finance tidak perlu ada untuk sekarang.
   - Pembayaran tidak perlu menjadi fitur transaksi/payment management; cukup history pembayaran/referensi administratif proyek.

## Proposed approach

Gunakan pendekatan contract-first frontend MVP tetap, tetapi lakukan realignment agar demo dan mock contract mengikuti PRD v1.3.6.

Prinsip:

1. Jangan mengklaim backend production sudah ada; tetap beri label mock/demo.
2. Selaraskan entity name, route, permission, enum, dan response mock dengan `/api/v1/*` PRD v1.3.6.
3. Hapus affordance UI yang memberi sinyal multi-OPD aktif.
4. Jadikan single active OPD sebagai invariant di mock data, service layer, dashboard, report, project, dan tests.
5. Naikkan modul Proyek GIS dari “dokumen satu-file” ke “header dokumen + multi-file/lampiran” di frontend mock.
6. Implementasikan upload multi-file interaktif di mock frontend, tetap tanpa backend/object storage nyata.
7. Hilangkan role `Finance` dan ubah payment menjadi history pembayaran read-only/admin history, bukan fitur pembayaran.
8. Tambahkan test E2E yang menjaga tidak ada regresi multi-OPD/transfer wording.

   - Pertahankan `/api/v1/opd` hanya sebagai alias kompatibilitas read-only yang mengembalikan satu OPD aktif/default jika masih dibutuhkan oleh screen lain.

   - Hapus opsi grouping `opd` atau ubah menjadi grouping internal yang valid: `jenis`, `status_geometri`, `keterkaitan_proyek`.

   - Form create/edit project tidak perlu `OPD proyek` select; set otomatis ke OPD aktif/default.

## Step-by-step implementation plan

### Phase 1 — Contract alignment single active OPD

1. Update `shared/src/schemas/opd.ts`:
   - Tambah `isPrimary` dan `version` bila diperlukan untuk profil OPD aktif.
   - Jangan menambahkan `subOpd/upt` ke MVP sekarang karena stakeholder menyatakan belum perlu.
   - Pastikan type merepresentasikan profil OPD aktif, bukan daftar OPD aktif.

2. Update `frontend/src/lib/mocks/opd.ts`:
   - Sisakan satu OPD aktif/default sesuai keputusan stakeholder.
   - Jika nama/kode final belum tertulis di repo, gunakan konstanta fixture `ACTIVE_OPD` agar mudah diganti tanpa menyentuh banyak file.
   - OPD lain dihapus dari active fixture dan tidak muncul di UI aktif.

3. Update `frontend/src/lib/services/api/opd.ts`:
   - Tambah `getCurrentOpd()` untuk mock/real path `/opd/current`.
   - Tambah `updateCurrentOpd(payload)` untuk `PUT /opd/current`.
   - Ubah `listOpd()` agar mock hanya mengembalikan satu OPD aktif/default dan diberi catatan compatibility.
   - Remove atau deprecate `softDeleteOpd` dan create OPD dari active UI path.

4. Rewrite `frontend/src/routes/opd/+page.svelte`:
   - Judul: “Profil OPD Pengguna”.
   - Tampilkan data profil OPD aktif/default.
   - Form edit profil hanya untuk role yang punya `opd:update`/permission setara.
   - Tidak ada tombol tambah/hapus/restore OPD.

5. Update tests OPD:
   - Remove test search/pagination/delete guard OPD.
   - Add test single active profile edit.
   - Add assertion tidak ada “Tambah mock”, “Hapus OPD”, “transfer aset”.

### Phase 2 — Dashboard/report single OPD cleanup

1. Update `frontend/src/routes/dashboard/+page.svelte`:

   - Biarkan internal meta jika dibutuhkan, tapi jangan expose sebagai statistik lintas OPD aktif.

3. Update `frontend/src/routes/reports/+page.svelte`:
   - Pastikan tidak ada filter/chart OPD lintas OPD.
   - Export metadata scope harus `own_opd`/OPD aktif/default implisit, bukan `all (mock demo)` bila role bukan Super Admin atau jika demo single OPD.

4. Update E2E dashboard/reports:
   - Remove select `Grouping layer = opd`.
   - Add assertion “single OPD/default” visible.
   - Add assertion no “Distribusi OPD” / no filter lintas OPD.

### Phase 3 — Project GIS schema and fixtures v1.3.6

### Phase 6 — Documentation and demo polish

1. Update `frontend/README.md` to PRD v1.3.6.
2. Update sidebar version label.
3. Add demo notes/banner explaining:

## Tests / validation

Run from `frontend/` after implementation:

```bash
npm run check
npm run test
npm run build
npm run test:e2e
npm run test:a11y
npm run verify:mvp
```

Recommended additional validation assertions:

1. Single OPD mode:
   - OPD page title is “Profil OPD Pengguna”.
   - No “Tambah OPD”, “Hapus OPD”, “transfer aset”, “relokasi OPD”, or OPD pagination in active UI.
   - No Sub OPD/Bidang/UPT input in MVP UI.
   - Project create/edit has no OPD selector.
   - Dashboard has no “Distribusi OPD” or OPD grouping selector.

2. Project document multi-file:
   - A project document header can show 2+ files.
   - Mock upload multi-file interaktif bisa memilih lebih dari satu file, memberi label/urutan, commit mock, lalu file muncul di header terkait.
   - File labels/order/checksum/scan status visible for authorized user.
   - Viewer cannot download sensitive inherited files.
   - Download audit event includes `project_id`, `document_id`, `file_id`.
   - Verify is blocked for document with no active clean file.
   - Document/file metadata update can surface `CONFLICT_VERSION`.

3. Contract alignment:
   - Mock envelope path uses `/api/v1/opd/current`, `/api/v1/projects/:id/documents/:documentId/files`, etc.
   - Payment history uses v1.3.6-compatible status values but remains read-only/non-transactional.
   - Role `Finance` is absent from role switcher, user fixtures, and permission helper logic.
   - README and sidebar mention PRD v1.3.6.

## Risks, tradeoffs, and mitigations

1. Risk: menghapus multi-OPD UI bisa terasa seperti fitur berkurang.
   - Mitigation: jelaskan di UI/demo bahwa MVP sengaja hanya menampilkan satu OPD aktif/default sesuai keputusan stakeholder dan PRD v1.3.6; jangan menawarkan Sub OPD/Bidang/UPT karena belum diperlukan di MVP.

2. Risk: perubahan shared enums memecahkan tests dan fixture lama.
   - Mitigation: lakukan berurutan: enums/types dulu, fixtures kedua, UI ketiga, tests terakhir.

3. Risk: Project GIS multi-file UI bisa membesar scope MVP.
   - Mitigation: implementasi minimal tetap frontend-only: header card + file list + mock upload multi-file interaktif + mock download/verify; real object storage, signed URL nyata, dan scan/quarantine tetap Go-live hardening/backend.

4. Risk: granular permission PRD terlalu luas untuk MVP mock.
   - Mitigation: tambahkan permission key yang dipakai UI saja lebih dulu, dan pertahankan compatibility helper sementara sampai auth fixture selesai.

5. Risk: tests E2E menjadi brittle karena UI copy berubah.
   - Mitigation: gunakan role/label semantic yang stabil, bukan detail visual.

## Decisions resolved from open questions

1. OPD aktif/default harus ditampilkan sebagai satu-satunya OPD aktif di MVP. Nama/kode final harus berasal dari fixture/config implementasi; bila belum tersedia, gunakan konstanta `ACTIVE_OPD` agar mudah diganti.
2. Sub OPD/Bidang/UPT tidak perlu masuk MVP frontend sekarang.
3. Project GIS MVP harus menyediakan mock upload multi-file interaktif.
4. Role `Finance` tidak dipertahankan; tidak ada fitur pembayaran aktif, hanya history pembayaran/referensi administratif proyek.
5. Implementasi berikutnya frontend-only sampai user review hasil frontend.

## Recommended first milestone

Milestone pertama yang paling aman:

**“Single Active OPD MVP realignment”**

Scope:

- Ubah OPD page menjadi Profil OPD Pengguna.
- Normalize OPD/project/assets mock data ke satu OPD aktif/default dan jangan tampilkan Sub OPD/Bidang/UPT.
- Hapus dashboard/report/project UI yang memberi sinyal multi-OPD.
- Hapus role `Finance`; payment hanya sebagai history pembayaran read-only.
- Update E2E untuk invariant single OPD.
- Update sidebar/README ke PRD v1.3.6.

Alasan:

- Ini menyelesaikan kontradiksi paling terlihat antara MVP lama dan PRD v1.3.6.
- Risikonya lebih kecil dibanding langsung refactor Project GIS multi-file.
- Setelah invariant single OPD stabil, lanjutkan milestone kedua untuk refactor Project GIS header+mock upload multi-file interaktif secara frontend-only.

Milestone kedua yang direkomendasikan:

**“Project GIS Header + Interactive Multi-file Mock Upload”**

Scope:

- Split `ProjectDocument` header dan `ProjectDocumentFile` di shared schema/mock data.
- Buat UI header dokumen proyek dengan daftar banyak file/lampiran.
- Tambah mock upload multi-file interaktif dengan label, urutan, pending list, commit mock, dan status upload.
- Tambah audit mock download/verify/delete dengan `project_id`, `document_id`, dan `file_id`.
- Ubah payment menjadi Riwayat Pembayaran read-only tanpa role Finance.
- Validasi E2E untuk upload multi-file, masking dokumen sensitif, verify blocked untuk header incomplete, dan tidak ada aksi pembayaran aktif.
